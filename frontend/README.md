# UniMatch — frontend, подключён к бэкенду

`app.js` больше не хранит профиль/свайпы в `localStorage` как основную базу —
теперь это делает бэкенд (FastAPI). `localStorage` хранит только лёгкий
"указатель" `{userId, guestId, lang}`, чтобы не заставлять человека проходить
онбординг заново при каждом визите.

## Что изменилось

- **`API_BASE`** (в начале файла) — адрес бэкенда, по умолчанию
  `http://127.0.0.1:8000`. Поменяй, если бэкенд крутится на другом порту/хосте.
- **`apiRequest()`** — единая обёртка над `fetch`: если бэкенд недоступен
  (не запущен / сеть отвалилась), показывает toast с понятным сообщением
  вместо тихого зависания.
- **Онбординг** (`finishOnboarding`) — теперь `POST /users`, получает от
  сервера `id` пользователя и настоящую подборку вузов (`GET /universities`)
  с посчитанными на бэке Match Score / Admission Reality.
- **Свайпы** (`doSwipe`, `toggleLike`) — пишутся на сервер (`POST`/`DELETE
  /users/{id}/swipes`), переживают перезагрузку страницы и работают с любого
  устройства, если знать `userId`.
- **Фильтры на Discover** (континенты, бюджет) — сохраняются на сервер и
  подборка перезапрашивается оттуда же.
- **"Мягкая" регистрация по email** — теперь настоящий `POST /users/{id}/register`.
- **При открытии страницы** — если в localStorage есть `userId`, профиль,
  лайки и подборка подтягиваются с сервера; если бэкенд недоступен —
  аккуратный откат на онбординг, а не белый экран.

## Что осталось локальным (сознательно)

- **`buildWhyReasons` / `matchBreakdown`** ("Why this university", разбивка
  Match Score по категориям) — чистые функции, которые не меняются между
  запросами и не нуждаются в сети. Бэкенд их дублирует (`/universities/{id}/why`),
  но фронт им пока не пользуется — можно переключить позже, если понадобится.
- **`computeDNA()`** — считается локально из уже загруженного `state.liked`
  (который, в свою очередь, приходит с бэкенда). Отдельного запроса не нужно.
- **Счётчик "passed" (дизлайков)** на экране DNA — считается только за
  текущую сессию в браузере, не переживает перезагрузку. У бэкенда пока нет
  эндпоинта для истории дизлайков.
- **Локальный массив `UNIVERSITIES`** остался в файле — служит источником
  статичных данных, которые бэкенд не хранит (сейчас это только `photo` у
  MIT). Все 50 записей там 1:1 совпадают с тем, что вернёт `seed_data.py`.

## Важно: бэкенд теперь источник истины

В отличие от исходного демо, приложение **не завершит онбординг**, если
бэкенд не запущен — вместо этого покажет toast с ошибкой. Это осознанный
компромисс этой версии интеграции: раз Match Score/Admission Reality/Matches
считает сервер, без него приложению просто нечего показывать.

## Иконка (favicon)

Раньше фавикон был отдельной картинкой "U" на фиолетовом фоне — цвет никак
не был связан с брендовой палитрой сайта (`--brand-primary` в `styles.css`)
и не менялся вместе с тёмной темой.

Теперь:

- **Форма** — та же, что и у логотипа в шапке приложения (`ICONS.logo` в
  `app.js`), а не отдельная буква.
- **Цвет — не захардкожен.** `buildFaviconSVG(bg, fg)` в `app.js` собирает
  SVG иконки из двух параметров цвета, а `updateFavicon()` берёт их прямо
  из применённых CSS-переменных `--brand-primary` (фон) и
  `--brand-on-primary` (сам значок), так что фавикон:
  - при обычной загрузке совпадает с брендовым зелёным (`#4C7A1E`);
  - автоматически перекрашивается при переключении на тёмную тему
    (`--brand-primary` там уже другой — салатовый `#F2FF76`), и обратно;
  - заодно обновляет `<meta name="theme-color">`, чтобы цвет системного
    тулбара на мобильных тоже совпадал с темой.
- **`index.html`** хранит только статичный фолбэк той же формы/цвета —
  на случай, если картинка запрашивается браузером до того, как выполнится
  `app.js` (у него `id="favicon"`, за него и цепляется `updateFavicon()`).

Поменять цвет иконки насовсем (например, если сменится бренд) — значит
поменять `--brand-primary`/`--brand-on-primary` в `styles.css`: фавикон,
логотип и остальной интерфейс перекрасятся одновременно, без правки самого
SVG.

## Как проверить, что всё работает

1. Запусти бэкенд (см. README бэкенда) — обязательно **до** открытия фронта.
2. Открой `index.html` (Live Server или любой локальный сервер).
3. Пройди онбординг — в Network (фильтр Fetch/XHR) должен появиться
   `POST http://127.0.0.1:8000/users`.
4. Свайпни карточку — появится `POST .../swipes`.
5. Перезагрузи страницу — должна открыться сразу Discover-страница с той же
   подборкой и тем же списком Matches, а не онбординг заново.

Всё это протестировано headless-браузерным прогоном (jsdom) против реального
запущенного бэкенда — полный цикл онбординг → свайп → перезагрузка страницы
→ восстановление профиля/лайков/колоды с сервера, плюс отдельно отмена лайка
и смена фильтра по континенту — так что интеграция не "выглядит рабочей", а
реально проверена сквозным сценарием.
